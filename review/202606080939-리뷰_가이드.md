## 1. [필수] 로그인 페이지에 `"use client"` 추가

**(1) 문제**
`src/app/auth/login/page.tsx`가 `onClick`을 쓰는데 `"use client"`가 없어 빌드/실행 시 에러가 납니다.

**(2) 왜**
App Router에서는 모든 컴포넌트가 기본적으로 **서버 컴포넌트**입니다. 서버 컴포넌트는 브라우저에서 실행되지 않기 때문에 `onClick`, `useState` 같은 상호작용을 붙일 수 없습니다. 이런 게 필요하면 파일 맨 위에 `"use client"`를 적어 "이건 브라우저에서도 돌아야 한다"고 표시해야 합니다. 참고로 `signup/page.tsx`엔 이미 잘 들어가 있습니다.

**(3) 해결 단계**
1. `src/app/auth/login/page.tsx`를 연다.
2. 파일 **맨 첫 줄**에 `"use client";` 한 줄을 추가한다.
3. 저장 후 `npm run dev`로 로그인 페이지가 정상적으로 뜨는지 확인한다.

**(4) Before / After** — `src/app/auth/login/page.tsx:1`

```tsx
// Before (1번째 줄부터)
import Link from "next/link";
import Image from "next/image";
import { createClient } from "@/utils/supabase/client";
```

```tsx
// After
"use client";   // ← 이 줄 추가

import Link from "next/link";
import Image from "next/image";
import { createClient } from "@/utils/supabase/client";
```

## 2. [필수] 루트 `middleware.ts` 작성 (Supabase 세션 연결)

**(1) 문제**
`src/utils/supabase/middleware.ts`의 `updateSession`을 잘 만들어 놨는데, 이걸 불러주는 **루트 미들웨어 파일이 없어** 한 번도 실행되지 않습니다.

**(2) 왜**
Supabase 로그인 상태는 쿠키에 저장되는데, 이 쿠키는 시간이 지나면 만료됩니다. 그래서 **매 요청마다 한 번씩 갱신**해야 로그인이 유지됩니다. Next.js에서 "매 요청마다 실행되는 코드"를 두는 자리가 바로 `middleware.ts`입니다. 이 파일이 없으니 새로고침하면 세션이 풀릴 수 있고, 로그인 안 한 사람도 마이페이지에 그냥 들어갈 수 있습니다.

**(3) 해결 단계**
1. `src` 폴더 바로 아래에 새 파일 `src/middleware.ts`를 만든다.
2. 아래 예시를 붙여넣는다 (Supabase 공식 패턴).
3. `matcher`로 정적 파일·이미지는 제외해서 불필요한 실행을 줄인다.

**(4) After** — 새 파일 `src/middleware.ts`

```ts
// src/middleware.ts (새로 만드는 파일)
import { type NextRequest } from "next/server";
import { updateSession } from "@/utils/supabase/middleware";

export async function middleware(request: NextRequest) {
  const { supabaseResponse } = await updateSession(request);
  return supabaseResponse;
}

// 미들웨어를 적용할 경로 (정적 파일·이미지는 제외)
export const config = {
  matcher: [
    "/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)",
  ],
};
```

**한 걸음 더 — 로그인 안 한 사람 막기 (선택)**
`updateSession`이 `user`도 같이 돌려줍니다. 이걸 이용하면 보호된 화면을 막을 수 있습니다.

```ts
export async function middleware(request: NextRequest) {
  const { supabaseResponse, user } = await updateSession(request);

  const protectedPaths = ["/myprofile", "/mypets", "/favorites"];
  const needsAuth = protectedPaths.some((p) =>
    request.nextUrl.pathname.startsWith(p),
  );

  if (needsAuth && !user) {
    const url = request.nextUrl.clone();
    url.pathname = "/auth/login";
    return Response.redirect(url);
  }

  return supabaseResponse;
}
```

> 미들웨어는 "화면 접근 차단"이고, 진짜 "데이터 차단"은 Supabase의 **RLS(Row Level Security)** 가 합니다. 역할이 다르니 데이터 연동 단계에서 RLS도 꼭 같이 켜야 합니다.

## 3. [필수] OAuth 콜백 라우트 + `NEXT_PUBLIC_SITE_URL` 설정

**(1) 문제**
`src/app/auth/login/page.tsx:13`과 `:24`에서 로그인 후 `${NEXT_PUBLIC_SITE_URL}/auth/callback`으로 돌아오게 했는데, **콜백 라우트가 없고** `NEXT_PUBLIC_SITE_URL`도 비어 있습니다.

**(2) 왜**
소셜 로그인은 이렇게 흘러갑니다.
1. "카카오로 계속하기" 클릭 → 2. 카카오 로그인/동의 → 3. 우리 사이트 콜백 주소로 `?code=...`를 달고 복귀 → 4. 콜백에서 그 `code`를 진짜 세션으로 **교환** → 5. 원래 페이지로 이동.
지금은 4번을 처리할 콜백이 없어서 로그인이 끝까지 안 됩니다. 또 `NEXT_PUBLIC_SITE_URL`이 비면 `undefined/auth/callback`이라는 깨진 주소로 돌아옵니다.

**(3) 해결 단계**
1. `src/app/auth/callback/route.ts` 파일을 만든다. (페이지가 아니라 화면 없이 처리만 하는 `route.ts`입니다.)
2. 프로젝트 루트에 `.env.local`을 만들고 URL/키를 넣는다. (`.gitignore`에 `.env*`가 있어 깃에 안 올라가니 안전합니다.)
3. Supabase 대시보드 → Authentication → URL Configuration의 **Redirect URLs**에 `http://localhost:3000/auth/callback`을 등록한다.

**(4) After** — 새 파일 `src/app/auth/callback/route.ts`

```ts
// src/app/auth/callback/route.ts (새로 만드는 파일)
import { NextResponse } from "next/server";
import { createClient } from "@/utils/supabase/server";

export async function GET(request: Request) {
  const { searchParams, origin } = new URL(request.url);
  const code = searchParams.get("code");
  const next = searchParams.get("next") ?? "/"; // 로그인 후 돌아갈 곳

  if (code) {
    const supabase = await createClient();
    const { error } = await supabase.auth.exchangeCodeForSession(code);
    if (!error) {
      return NextResponse.redirect(`${origin}${next}`);
    }
  }

  // 실패 시 로그인 페이지로
  return NextResponse.redirect(`${origin}/auth/login?error=oauth`);
}
```

**환경변수** — 새 파일 `.env.local` (프로젝트 루트)

```bash
NEXT_PUBLIC_SUPABASE_URL=https://여러분프로젝트.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=여기에-anon-key
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

## 4. [필수] 로그아웃에 `signOut()` 추가

**(1) 문제**
`src/app/myprofile/page.tsx:400`과 `:543`의 로그아웃 버튼이 `router.push("/auth/login")`만 해서 세션이 안 지워집니다.

**(2) 왜**
페이지만 이동하면 화면은 로그인 페이지로 가지만 쿠키에 저장된 로그인 상태는 그대로 남아 있습니다. 진짜 로그아웃은 `supabase.auth.signOut()`으로 세션을 지워야 합니다. 지금은 인증 연동 전이라 티가 안 나지만, 로그인이 붙는 순간 "로그아웃했는데 여전히 로그인 상태" 버그가 됩니다.

**(3) 해결 단계**
1. `myprofile/page.tsx` 상단에 클라이언트 supabase를 가져온다.
2. `handleLogout` 함수를 만들어 `signOut()` 후 이동·새로고침한다.
3. 두 군데 로그아웃 버튼의 `onClick`을 `handleLogout`으로 바꾼다.

**(4) Before / After** — `src/app/myprofile/page.tsx`

```tsx
// Before — 400번째 줄 / 543번째 줄
onClick={() => router.push("/auth/login")}
```

```tsx
// After — 컴포넌트 안에 함수 추가
import { createClient } from "@/utils/supabase/client";

const supabase = createClient();

const handleLogout = async () => {
  await supabase.auth.signOut(); // ← 세션 삭제
  router.push("/auth/login");
  router.refresh();              // ← 서버 쪽 상태도 갱신
};

// 그리고 두 버튼 모두
onClick={handleLogout}
```

## 5. [필수] 하이드레이션 수정 재적용 + 머지 충돌 예방

**(1) 문제**
`fix/Hydration`에서 고쳤던 폰트 링크가 머지 과정에서 되돌아와, 지금 `src/app/layout.tsx:16~21`에 `<head>` 안 폰트 `<link>`가 다시 들어와 있습니다.

**(2) 왜**
하이드레이션은 "서버가 그린 HTML"과 "브라우저가 다시 그리는 React 결과"가 **같아야** 한다는 규칙입니다. `<head>`에 외부 CSS `<link>`를 직접 넣으면 브라우저 확장프로그램이나 로딩 타이밍 탓에 둘이 어긋나 경고가 납니다. 그래서 예전에 CSS `@import`로 옮겨 고쳤던 건데, 그게 머지로 되살아났습니다.

**(3) 해결 단계 — 둘 중 하나로 통일**
- 방법 A (예전에 고친 대로): `globals.css`에 `@import`로 폰트를 불러오고, `layout.tsx`의 `<head>...</head>` 블록은 통째로 삭제.
- 방법 B (Next.js 권장, 추천): Pretendard를 `next/font`로 불러오기. 폰트 최적화까지 자동입니다.

**(4) Before / After** — 방법 A 기준

```tsx
// Before — src/app/layout.tsx:15~22
<html lang="ko" className="h-full">
  <head>
    <link
      rel="stylesheet"
      href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard.min.css"
    />
  </head>
  <body className="min-h-full flex flex-col antialiased">{children}</body>
</html>
```

```tsx
// After — <head> 블록 삭제
<html lang="ko" className="h-full">
  <body className="min-h-full flex flex-col antialiased">{children}</body>
</html>
```

```css
/* src/app/globals.css 맨 위 — 폰트는 여기서 불러오기 */
@import "tailwindcss";
@import url("https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard.min.css");
```

**머지 충돌 예방 습관**
이번처럼 "고친 게 되살아나는" 일을 막으려면, 머지나 충돌 해결 직후 `git diff`로 **내가 의도한 변경만 들어갔는지** 한 번 훑어봅시다. 충돌 해결 화면에서 양쪽 코드를 합칠 때, 이미 고친 부분이 옛날 버전으로 덮이지 않았는지 특히 주의하면 됩니다.

## 1. 웹훅 결제 금액 검증 복원 + `/payment` 제거

### 왜 고쳐야 하나
지금 웹훅은 HMAC 서명만 보고 `paid`로 올립니다. 서명은 "PortOne이 보낸 요청이다"만 보장하지, "얼마가 결제됐는지"는 알려주지 않습니다. 그래서 1원짜리 결제가 만들어져도 그대로 통과합니다. 결제는 돈이 오가는 지점이라, **서버가 직접 PortOne에 "이 결제 정말 얼마짜리로 승인됐나"를 다시 물어본 다음** 우리가 기대한 금액과 같을 때만 `paid`로 올려야 안전합니다.

### 어떻게
`portone/webhook/route.ts`의 `Transaction.Paid` 처리부에 PortOne 단건조회를 끼워넣습니다.

```ts
// type === "Transaction.Paid" 블록 안
// 1) PortOne API로 실제 결제 상태/금액을 조회
const res = await fetch(
  `https://api.portone.io/payments/${encodeURIComponent(paymentId)}`,
  { headers: { Authorization: `PortOne ${process.env.PORTONE_API_SECRET}` } },
);
const portonePayment = await res.json();

// 2) 결제 상태와 금액을 우리 DB 기대값과 대조
const paidOk =
  portonePayment.status === "PAID" &&
  portonePayment.amount?.total === payment.amount; // payments.amount = 서버가 정한 결제 금액

if (!paidOk) {
  // 금액 불일치/미승인 → paid로 올리지 않고 끝냄 (필요하면 로깅)
  return NextResponse.json({ data: { ok: true } });
}

// 3) 여기까지 통과했을 때만 paid 처리
await db.from("payments").update({ status: "paid", paid_at: now }).eq("id", payment.id);
```

여기서 핵심은 `payment.amount`(우리가 결제 직전에 서버에서 정한 금액)와 PortOne이 알려준 실제 승인 금액을 비교한다는 점입니다. 둘이 다르면 누군가 금액을 조작한 것이니 절대 `paid`로 올리지 않습니다.

### `/payment` 페이지 정리
`src/app/payment/page.tsx`는 `createPayment`를 거치지 않아 `payments` 행 자체가 안 생깁니다. 즉 위에서 만든 검증을 통과할 수가 없는(=정상 결제가 아닌) 경로라, 두 가지 중 하나로 정리하세요.

- **(권장) 페이지 삭제** — 실제 결제는 채팅/예약 플로우(`createReservation` → `createPayment`)로만 들어오게 통일.
- 남겨야 한다면, `handlePay`에서 먼저 `createPayment`(서버액션)를 호출해 `payments` 행을 만들고, 거기서 받은 `paymentId`/금액으로 `requestPayment`를 호출하도록 바꾸세요. 더미 고객정보(`테스트`/`010-0000-0000`/`test@test.com`)도 실제 로그인 유저 정보로 교체합니다.

## 2. createReservation 자기예약 서버 차단

### 왜 고쳐야 하나
UI에서 `isSelf`로 버튼을 숨기는 건 사용자가 화면에서 자기 자신을 예약하기 어렵게 만든 것이지, 막은 게 아닙니다. API/URL로 `createReservation`을 직접 부르면 시터가 자기 자신을 예약할 수 있습니다.

### 어떻게
`actions/reservations.ts`의 `createReservation` 안, 이미 `service`를 조회해 둔 지점(`service.sitter_id !== input.sitter_id` 검사 근처) 뒤에 시터 소유자 확인을 한 줄 더 둡니다.

```ts
// service 조회 후, sitter의 user_id(소유자)를 확인
const { data: sitter } = await db
  .from("sitters")
  .select("user_id")
  .eq("id", input.sitter_id)
  .single();

if (sitter?.user_id === user.id) {
  return {
    error: { code: "FORBIDDEN", message: "본인 시터에게는 예약할 수 없습니다." },
  };
}
```

이렇게 서버액션 안에 가드를 두면 화면을 거치지 않은 직접 호출도 막힙니다. UI의 `isSelf`는 그대로 두세요 — 사용자 경험상 버튼을 안 보여주는 것도 맞으니, "UI는 보여주지 않고, 서버는 거절한다" 두 겹이면 좋습니다.

## 3. 공개 API에서 민감 정보 줄이기

### 정확 위경도 → 표시용 지역만
`api/sitters/[id]/route.ts`에서 `latitude`/`longitude`를 그대로 내보내면 시터 집 좌표가 노출됩니다. 두 가지 중에 고르면 됩니다.

- 응답에서 좌표를 빼고 `display_area`(예: "마포구 연남동")만 내보낸다.
- 지도 표시가 꼭 필요하면, 좌표를 살짝 흐리게(예: 소수점 2자리로 반올림 + 약간의 랜덤 오프셋) 내보내 "대략 이 동네"까지만 알 수 있게 한다.

```ts
// 예: 동 단위로만 노출
return NextResponse.json({
  data: {
    id: sitter.id,

    // user_id 는 화면에 안 쓰면 제거

    // latitude / longitude 제거 또는 fuzzing
    ...
  },

```

## 4. notifications RLS 확인/추가

### 확인
Supabase 대시보드 또는 마이그레이션 파일에서 `notifications` 테이블에 아래와 같은 SELECT 정책이 있는지 보세요. 없으면 추가합니다.

```sql
-- notifications: 본인 알림만 읽기
alter table notifications enable row level security;

create policy "notifications_select_own"
on notifications for select
to authenticated
using (auth.uid() = user_id);
```

클라이언트의 `user_id` 필터는 "화면에 안 그리기"일 뿐이라, anon/다른 유저 토큰으로 `GET /rest/v1/notifications`를 직접 때리면 남의 알림이 읽힐 수 있습니다. 위 정책이 들어가야 서버 차원에서 막힙니다.

## 5. SEO 최소 구성

### metadataBase (layout.tsx)
```ts
export const metadata: Metadata = {
  metadataBase: new URL(process.env.NEXT_PUBLIC_SITE_URL ?? "http://localhost:3000"),
  title: { default: "봐주개", template: "%s | 봐주개" },
  description: "반려동물 돌봄 매칭 플랫폼",
};
```

### sitemap.ts (src/app/sitemap.ts)
```ts
import type { MetadataRoute } from "next";

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const base = process.env.NEXT_PUBLIC_SITE_URL ?? "http://localhost:3000";
  // 펫시터/게시글 목록을 DB에서 받아 동적으로 추가 가능
  return [
    { url: `${base}/`, priority: 1 },
    { url: `${base}/petsitters` },
    { url: `${base}/board` },
  ];
}
```

### robots.ts (src/app/robots.ts)
```ts
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  const base = process.env.NEXT_PUBLIC_SITE_URL ?? "http://localhost:3000";
  return {
    rules: { userAgent: "*", allow: "/" },
    sitemap: `${base}/sitemap.xml`,
  };
}
```

### 상세 페이지 generateMetadata
`board/[id]`·`petsitters/[id]`를 서버 컴포넌트로 전환하면(데이터 패칭을 서버에서), 같은 파일에 `generateMetadata`를 둬서 제목/설명을 동적으로 줄 수 있습니다.

```ts
export async function generateMetadata({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  const sitter = await getSitter(id); // 서버에서 조회
  return {
    title: sitter?.full_name ?? "펫시터",
    description: sitter?.introduction ?? "",
  };
}
```

CSR→SSR 전환은 한 번에 다 하기 부담스러우면, 먼저 metadataBase·sitemap·robots 세 개부터 넣고(파일만 추가하면 됨), 페이지 전환은 그다음에 하나씩 옮겨도 됩니다.

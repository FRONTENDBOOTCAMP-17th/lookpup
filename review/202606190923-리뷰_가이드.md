## 1. [필수·이월] 회원탈퇴 실제 연결 (deleteUser + signOut)

지금 `withdraw/page.tsx`의 `handleDelete`는 모달만 닫고 완료 화면으로 넘어갑니다. 실제로는 계정을 삭제하고 로그아웃해야 합니다. 계정 삭제는 service role 키가 필요해 클라이언트에서 직접 못 하니, **서버 액션**으로 분리합니다.

### 1단계 — 탈퇴 서버 액션 만들기

`src/app/actions/account.ts` (신규):

```ts
"use server";

import { createClient } from "@/utils/supabase/server";
import { createServiceClient } from "@/utils/supabase/service";

export async function deleteAccount() {
  const supabase = await createClient();
  const {
    data: { user },
  } = await supabase.auth.getUser();

  if (!user) {
    return { error: { code: "UNAUTHORIZED", message: "로그인이 필요합니다." } };
  }

  // 진행 중 예약이 있으면 차단(선택) — reservations에서 본인 active 건 확인
  const db = createServiceClient();
  const { data: active } = await db
    .from("reservations")
    .select("id")
    .eq("owner_id", user.id)
    .in("status", ["pending", "confirmed"])
    .limit(1);

  if (active && active.length > 0) {
    return { error: { code: "HAS_ACTIVE", message: "진행 중인 예약이 있어 탈퇴할 수 없습니다." } };
  }

  // auth 사용자 삭제 (service role 필요)
  const { error } = await db.auth.admin.deleteUser(user.id);
  if (error) {
    return { error: { code: "INTERNAL_ERROR", message: error.message } };
  }

  return { data: { ok: true } };
}
```

users 행이나 연관 데이터를 함께 지우려면 DB의 `on delete cascade`로 걸어두면 연관 데이터까지 한 번에 정리돼 편합니다(스키마에서 FK에 cascade 추가). 법령 보관이 필요한 결제·예약 이력은 cascade 대신 `deleted_at`만 찍고 남기는 방식도 있습니다. 둘 중 어느 쪽이든 팀에서 정하면 됩니다.

### 2단계 — 페이지에서 호출 + signOut + 이동

`withdraw/page.tsx`:

```ts
import { createClient } from "@/utils/supabase/client";
import { deleteAccount } from "@/app/actions/account";

const [deleting, setDeleting] = useState(false);
const [error, setError] = useState<string | null>(null);

const handleDelete = async () => {
  setError(null);
  setDeleting(true);
  try {
    const result = await deleteAccount();
    if ("error" in result) {
      setError(result.error?.message ?? "탈퇴 중 오류가 발생했습니다.");
      setShowModal(false);
      return;
    }
    // 클라이언트 세션도 정리
    await createClient().auth.signOut();
    setShowModal(false);
    setDone(true);
  } catch (e) {
    setError((e as Error).message);
  } finally {
    setDeleting(false);
  }
};
```

## 2. [필수] Cloudinary 서명 알고리즘 확인

`upload.ts`가 `sha256`으로 서명하는데, Cloudinary 서명 업로드는 **계정이 SHA-256으로 설정돼 있지 않으면 SHA-1이 기본**이라 `Invalid Signature`가 납니다.

### 확인 방법

펫시터 등록을 실제로 한 번 해보고(로그인 후 사진 첨부 → 등록 완료), 업로드가 성공하는지 봅니다. 실패한다면 둘 중 하나로 맞춥니다.

**(A) 계정을 SHA-256으로 유지하고 싶다면** Cloudinary 콘솔 Settings → Security에서 서명 알고리즘을 SHA-256으로 설정하고, 그 사실을 팀 노트에 적어둡니다(다른 사람이 SHA-1로 되돌리지 않도록).

**(B) 기본값(SHA-1)에 맞추려면** `upload.ts`만 한 줄 바꿉니다:

```ts
const signature = crypto.createHash("sha1").update(str).digest("hex");
```

시연에서 펫시터 등록을 보여줄 생각이면 둘 중 어느 방식으로 가든 반드시 한 번 실제 업로드까지 돌려보고 들어가세요.

## 3. [제안] 업로드 전에 검증 먼저

지금은 이미지를 다 올린 뒤 `createSitter`가 "소개 20자 이상" 같은 검증으로 거절하면, 올라간 이미지가 고아로 남습니다. 클라이언트에서 먼저 막으면 헛된 업로드가 없습니다.

`handleSubmit` 맨 앞:

```ts
const handleSubmit = async () => {
  setSubmitError(null);

  // 업로드 전에 빠르게 막을 수 있는 것 먼저 검증
  if (intro.trim().length < 20) {
    setSubmitError("자기소개는 20자 이상 입력해주세요.");
    return;
  }
  if (!region) {
    setSubmitError("활동 지역을 선택해주세요.");
    return;
  }

  setIsSubmitting(true);
  try {
    // ...기존 업로드 + createSitter
  } finally {
    setIsSubmitting(false);
  }
};
```

이러면 4장의 글자 수 기준도 함께 정리됩니다. 폼(`slice(0, 500)`)·카운터(`/500`)·여기 검증(20~500)을 한 기준으로 맞추고, 서버 쪽 숫자(`actions/sitters.ts`의 1000)도 같이 통일하면 됩니다.

## 4. [제안] 쓰기/수정 페이지 진입 가드

비로그인 사용자가 폼을 다 채운 뒤에야 막히지 않도록, 페이지 진입 시점에 로그인 여부를 봅니다. 프로젝트에 이미 `UserProvider`/`userStore`가 있으니, 그걸 그대로 쓰면 다른 코드와 결이 맞습니다.

`board/write/page.tsx` 상단:

```ts
import { useEffect } from "react";
import { useRouter } from "next/navigation";
import { createClient } from "@/utils/supabase/client";

const router = useRouter();

useEffect(() => {
  createClient().auth.getUser().then(({ data: { user } }) => {
    if (!user) {
      router.replace("/auth/login?redirect=/board/write");
    }
  });
}, [router]);
```

`board/[id]/edit/page.tsx`는 이미 `getUser()`를 부르지만 `if (!user) return;`으로 조용히 멈춥니다. 거기서도 빈 폼을 남기지 말고 위처럼 `router.replace("/auth/login?...")`로 보내거나, 최소한 "로그인이 필요합니다" 안내를 띄워주세요. 로그인이 끝나면 원래 가려던 화면으로 돌려보내고 싶으면 `?redirect=` 쿼리를 콜백에서 읽어 처리하면 됩니다.

> 서버 액션(`createRequest`/`updateRequest`)의 인증 검사는 그대로 두세요. 클라이언트 가드는 사용자 경험을 매끄럽게 해줄 뿐이고, 인증을 실제로 막는 건 서버 쪽이라 둘 다 두는 게 맞습니다.

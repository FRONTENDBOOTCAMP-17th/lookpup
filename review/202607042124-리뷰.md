# lookpup(봐주개) 18차 코드 리뷰 (2026-07-04)

발표가 다음 주 수요일이니 실제 개발은 화요일까지네요. 이번 회차 한 줄로 정리하면, **프로덕션 빌드가 드디어 초록불로 돌아왔습니다.** `npx tsc --noEmit` 0건, `npm run build`가 59개 라우트 전부 성공으로 끝났고요. 17차에서 16건이나 잡히던 타입 에러가 이번엔 하나도 안 남았습니다. 다만 이 상태로 레포를 공개하기엔 아직 이릅니다. 지난 회차부터 이어지던 보안 이슈 세 가지가 그대로 남아 있어서, 이번 리뷰는 "빌드는 됐으니 이제 공개 전에 뭘 닫아야 하는가"에 초점을 맞췄습니다.

지난 지적 반영부터 짚고, 공개 전 우선순위 세 가지와 조원별·팀 공통, 그리고 E2E 결과 순으로 가보겠습니다.

## 2. 취업 레포로 공개하기 전 먼저 할 3가지

발표 다음엔 이 레포가 이력서에 걸릴 텐데, 그 관점에서 지금 가장 먼저 손대야 할 세 가지를 꼽아봤습니다. README·스크린샷·기여도 표 같은 공통 항목은 동봉한 `202607042124-취업레포-가이드.md`에 다섯 조 공통으로 정리해뒀으니 그쪽을 참고해주시고, 여기서는 lookpup에서 유독 눈에 띄는 것 위주로 적습니다.

### 보안 구멍 3종을 공개 전에 닫아야 합니다

오픈소스로 공개하는 순간, 코드에 남은 취약점은 "여기를 이렇게 찌르면 뚫린다"는 설명서가 되어버립니다. 지금 세 가지가 그대로 남아 있습니다.

- 먼저 1원 결제입니다. `ChatClient.tsx:820`에서 `createPayment(reservationId, "CARD", totalAmount)`를 호출하는데, 이 `totalAmount`는 클라이언트가 계산한 값입니다. 예약 owner가 개발자도구로 `totalAmount`를 1로 바꿔 호출하면 `payments.ts:86`이 그 값을 그대로 받아 저장하고, `:91-96`에서는 한술 더 떠 예약의 `total_price` 자체를 1로 덮어써버립니다. 웹훅에서 포트원 재조회 후 금액을 대조하는 방어선은 있지만, "저장된 값끼리" 비교하는 구조라 처음부터 낮게 저장하면 그 검증을 그냥 통과합니다.
- 다음은 공개 RPC의 개인정보입니다. `get_petsitters_filtered`는 지도/목록 조회용 RPC인데, `database.types.ts:1096-1108`에 명시된 반환 타입에 `full_name`·`user_id`·`available_area`가 포함돼 있고, 실제로 anon 키로 호출하면 실명과 동 단위 주소가 그대로 나옵니다. 좌표는 이미 fuzz 처리하고 `display_area`(구 단위)를 따로 만들어둔 걸 보면 팀이 프라이버시를 신경 쓴 흔적은 분명한데, 딱 이 세 필드만 빠져나가고 있는 상황입니다.
- 마지막으로 자기예약입니다. `createReservation`(`reservations.ts:35-130`)이 서비스가 시터 소유인지는 확인하면서(87행) 정작 예약자 본인이 그 시터인지는 확인하지 않습니다. UI에서는 막고 있어도 API를 직접 호출하면 우회됩니다.

세 건 다 파일과 줄 번호까지 가이드에 코드로 적어뒀습니다. 지도 검색에 영향 없이 고칠 수 있는 것들이라, 발표 전에 닫아두면 안심하고 공개할 수 있습니다.

### README에 데모·스크린샷·기여도·LICENSE가 비어 있습니다

지금 README는 소개·기능·스택은 잘 정리돼 있는데, 클릭해서 바로 볼 수 있는 라이브 데모 링크가 없고, 화면 캡처도 없고, 조원별로 뭘 맡았는지도 안 보이고, LICENSE 파일도 없습니다. 채용담당자가 레포를 열었을 때 가장 먼저 보는 것들이라 영향이 큽니다. 구체적인 방법은 가이드 문서에 공통으로 적어뒀습니다.

GitHub Contributors 그래프는 이메일 기준으로 집계되는데, 지금 같은 사람이 이름을 여러 개로 커밋하고 있습니다.

## 4. 팀 공통

- 커밋이 한 계정에 쏠려 있습니다. 17차 이후 61커밋 중 39개가 최영은님 계정입니다. 팀이 상의해서 이 시기엔 결제/빌드 쪽에 집중 배정한 결과일 수도 있고, 자연스럽게 그렇게 흘러간 것일 수도 있는데, 어느 쪽이든 발표에서 각자 맡은 부분을 설명할 때는 최근 상황과 어긋나지 않게 미리 팀 안에서 맞춰두는 게 순서일 겁니다.
- git author 이름 통일은 2장에 적었듯 이번엔 꼭 해두는 걸 권합니다. 특히 박규나님 커밋의 절반 가까이가 이메일 오타(`gamil.com`)로 다른 계정 취급되고 있어서, 그래프상으로는 실제 기여보다 훨씬 적어 보입니다.
- **eslint 69 errors / 43 warnings**(실측)는 그대로입니다. `no-explicit-any`가 25건인데 `utils/kakaoGeocode.ts`에 9건, `components/KakaoMap.tsx`에 6건이 몰려 있고, 나머지 다수는 `set-state-in-effect`(Next 최신 규칙)입니다. 지금 CI가 `tsc`·`build`만 게이트로 걸어두고 lint는 빠져 있어서 계속 쌓이는 구조인데, 당장 급한 건 아니지만 시간이 남으면 lint까지 초록불로 맞춰두면 레포 인상이 확실히 달라집니다.
- **[제안] Multiple GoTrueClient**: `src/lib/supabase.ts:7`(`createClient`)와 `src/utils/supabase/client.ts:5`(`createBrowserClient`)가 각각 브라우저 클라이언트를 만들고 있어서 콘솔에 경고가 뜹니다. 하나로 합쳐두면 어떤가요.
- 양호한 점도 있습니다. `console.log`나 `TODO` 잔재가 검색되지 않았고, `.env` 계열은 커밋 이력에 안 보입니다. PR 기반 머지 흐름도 계속 잘 유지되고 있습니다.

먼저 전체적인 인상부터 말하면, **화면이 잘 만들어져 있습니다.** 봐주개라는 반려동물 돌봄 플랫폼 콘셉트가 색감(오렌지 톤)과 레이아웃에서 일관되게 느껴지고, 메인/게시판/프로필/로그인 화면의 디자인 완성도가 높습니다. Tailwind를 꽤 능숙하게 쓰고 있다고 생각합니다. 반응형(데스크탑/모바일 분기)까지 신경 쓴 점도 좋습니다.

## 팀 공통

### 1. README가 기본 템플릿 그대로입니다 [제안]

`README.md`가 아직 `create-next-app`이 만들어준 기본 안내문 그대로입니다. 코드는 이미 꽤 올라왔는데 정작 **이 프로젝트가 무엇인지, 누가 무엇을 맡았는지**가 문서에 없습니다. 리뷰하는 입장에서도, 나중에 발표/포트폴리오로 쓸 때도 README가 첫인상이 됩니다. 아래 정도만 채워도 훨씬 좋아집니다.

- 서비스 한 줄 소개 (예: "봐주개 — 지역 기반 반려동물 돌봄 매칭 플랫폼")
- 주요 기능 (펫시터 찾기 / 구인게시판 / 소셜 로그인 / 마이페이지)
- 팀원과 담당 영역
- 기술 스택 (Next.js 16, React 19, Supabase, Tailwind, zustand, react-query 등. `package.json`에 이미 다 들어 있습니다)
- 실행 방법 + 필요한 환경변수 목록

### 2. 폴더 구조는 좋습니다, 한 가지만 [사소]

`src/app`, `src/components/layout`, `src/hooks`, `src/utils/supabase` 로 나뉜 구조가 깔끔합니다. 다만 `src/hooks/useAuth.ts` 파일이 **완전히 비어 있습니다(0바이트)**. 빈 파일을 커밋해두면 "여기 뭔가 있겠지" 하고 다른 팀원이 헷갈릴 수 있으니, 아직 안 만들 거면 지우고, 만들 거면 최소한 뼈대라도 넣어두는 게 좋습니다. 이 훅이 채워지면 로그인 상태 관리가 훨씬 수월해진다고 생각합니다. 가이드에서 다시 다루겠습니다.

### 3. 컨벤션 — 커밋과 PR 템플릿은 잘 잡혀 있습니다 [제안]

`.github`에 PR 템플릿과 이슈 템플릿을 만들어 뒀고, 커밋 메시지도 `feat:`, `fix:`, `chore:` 형태로 일관되게 쓰고 있는 점 좋습니다. 한 가지, 초반 커밋에 `doce:` 라는 오타가 몇 개 보입니다(아마 `docs:`). 사소하지만 컨벤션은 "전원이 똑같이" 지킬 때 의미가 있으니, 팀에서 쓰는 타입 목록(`feat/fix/docs/chore/refactor/style`)을 README나 노션에 한 번 정리해두면 좋겠습니다.

### 4. 협업 흐름은 건강합니다 [칭찬]

브랜치를 `Feature/board`, `Feature/login`, `feat/Oauth` 처럼 기능별로 따고, PR을 통해 `dev`로 머지하는 흐름이 잘 잡혀 있습니다. main 직접 푸시 없이 PR 기반으로 가는 건 바람직합니다. 다만 브랜치 이름이 `Feature/` 와 `feat/` 가 섞여 있습니다. 둘 중 하나로 통일하길 권합니다.

### 5. 하이드레이션(hydration) 이슈 — 고쳤다가 다시 돌아온 것으로 보입니다 [필수]

`fix/Hydration` 브랜치에서 하이드레이션 오류를 한 번 잡았더군요. 그때 폰트 CDN 링크를 `layout.tsx`의 `<head>` 밖으로 빼고 `globals.css`의 `@import`로 옮기는 수정을 했습니다. 좋은 방향이었습니다.

그런데 **지금 `dev`의 `src/app/layout.tsx`를 보면 그 `<head>` 안의 폰트 링크가 다시 들어와 있습니다.** (16~21번째 줄) 이후 다른 브랜치를 머지하면서 옛날 버전이 되살아난 것으로 보입니다. 머지 충돌을 해결할 때 "이미 고친 코드가 되돌아오지 않았는지" 확인하는 게 중요하다는 걸 보여주는 사례라 생각합니다. 하이드레이션 경고가 다시 뜨고 있을 가능성이 높으니 dev에서 한 번 더 확인해 주세요. 해결 방법은 가이드에 정리해뒀습니다.

## E2E 테스트 결과

이번엔 코드만 읽지 않고 실제로 앱을 띄워서 확인했습니다. 리뷰 전용으로 Playwright E2E를 따로 작성했고(`review/e2e/`, 여러분 테스트와는 별개입니다), 캡처는 `review/images/`에 있습니다. `.env.local`을 넣어주셔서 실제 Supabase에 붙여 봤습니다. 다만 `NEXT_PUBLIC_SITE_URL`이 빠져 있어서 로컬 실행용으로만 임시값을 넣었습니다.

로그인은 카카오/구글 OAuth만 있고 이메일 로그인이 없어서 자동화로는 끝까지 못 갑니다. 그리고 아래처럼 **로그인 페이지 자체가 지금 열리지 않습니다.**

| 시나리오 | 결과 | 비고 |
| --- | --- | --- |
| 홈(`/`) 렌더 | 정상 | (`images/01-home.png`) |
| 로그인(`/auth/login`) | **500 에러** | "use client" 누락 (`images/02-login-500.png`) |
| 회원가입(`/auth/signup`) | 정상 | (`images/03-signup.png`) |
| 게시판(`/board`) | 정상 | (`images/04-board.png`) |
| 비로그인 `/myprofile` | **그대로 노출** | 200, mock 사용자로 렌더 (`images/05-myprofile-no-auth.png`) |
| 비로그인 `/mypets`, `/favorites` | 그대로 노출 | 둘 다 200 |

**[필수] 로그인 페이지가 500입니다.** `images/02-login-500.png`처럼 "Event handlers cannot be passed to Client Component props. `<button onClick={signInWithKakao}>`" 에러가 납니다. `/auth/login/page.tsx`가 `onClick` 핸들러를 쓰면서 맨 위에 `"use client"`가 없어서 그렇습니다. 지금은 **아무도 로그인을 할 수 없는 상태**라 가장 먼저 고쳐야 합니다. 가이드 문서에 `"use client"` 한 줄 추가하는 방법을 적어뒀습니다.

추가로 제가 `npm run build`(프로덕션 빌드)도 돌려 봤는데, 컴파일은 되지만 `/auth/login` 프리렌더 단계에서 같은 에러로 **빌드 자체가 중단됩니다** (`Error occurred prerendering page "/auth/login" ... Export encountered an error on /auth/login, exiting the build`). 즉 지금은 **배포용 빌드도 안 되는 상태**라, 이 한 줄(`"use client"`)이 더더욱 우선입니다.

**[필수·보안] 보호돼야 할 페이지가 비로그인에 다 열립니다.** `/myprofile`에 로그인 없이 들어갔는데 `images/05-myprofile-no-auth.png`처럼 "내 프로필"이 mock 사용자(김민수)로 그대로 뜨고, 헤더도 로그인된 것처럼 보입니다. `/mypets`, `/favorites`도 200으로 열립니다. 루트 `middleware.ts`가 없어서 세션 검사·리다이렉트가 동작하지 않는 게 원인입니다. supabase 미들웨어 헬퍼는 잘 만들어 두셨으니, 루트에 `middleware.ts`를 두고 그 헬퍼를 연결만 하면 됩니다. (가이드 참고)

**그 외 관찰.** 화면이 mock 데이터로 채워져 있어서, 실제 로그인한 사용자 정보·실데이터와 아직 연결되지 않은 상태로 보입니다. 로그인(use client)과 미들웨어를 먼저 살리면 그다음 실데이터 연결로 자연스럽게 이어집니다.

**이번 E2E의 한계.** 로그인이 막혀 있어 로그인 이후 흐름(예약·찜·작성)은 보지 못했습니다. `"use client"`와 `middleware.ts`를 고친 뒤 다시 돌려보겠습니다.

## 마무리

첫 리뷰인데 화면 완성도가 높아서 보는 재미가 있었습니다. 디자인 감각과 컴포넌트 분리 습관은 이미 기대 이상입니다. 지금 팀에 필요한 건 "예쁜 화면"이 아니라 **"그 화면을 진짜로 동작하게 만드는 연결 고리"**라 생각합니다. 정리하면 우선순위는 이렇습니다.

1. 로그인 페이지 `"use client"` 추가 (지금 빌드가 안 될 수도 있는 버그)
2. Supabase 미들웨어 연결 + OAuth 콜백 라우트 만들기 (인증이 끝까지 동작하게)
3. 로그아웃에 `signOut()` 붙이기, 더미데이터를 실제 데이터로 교체 시작
4. README 채우기, 빈 `useAuth.ts` 정리

한 번에 다 하려 하지 말고, 위에서부터 하나씩 닫아 나가면 됩니다. 이미 토대(Supabase 유틸, 깔끔한 컴포넌트)는 잘 깔려 있어서, 연결만 하면 빠르게 살아난다고 생각합니다. 다음 리뷰 때는 인증 흐름이 실제로 도는 모습을 볼 수 있길 기대합니다. 고생했습니다.

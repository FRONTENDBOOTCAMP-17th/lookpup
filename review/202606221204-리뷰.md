# lookpup(봐주개) 10차 코드 리뷰 (2026-06-22) — 시연 대비 집중 점검

오늘 오후 사용자 기능 중간 시연을 앞두고 있어서, 9차(2026-06-19) 이후 dev에 올라온 변경 가운데 **시연 동선에 직결되는 것 위주로** 빠르게 봤습니다. 9차에서 시연 전에 닫자고 했던 두 가지([필수] 회원탈퇴 실연결, [필수] Cloudinary 서명 알고리즘)부터 확인한 다음, 그 사이 더미를 걷어내고 실데이터로 붙인 구인게시판·후기 관리·펫 등록을 훑었습니다. 늘 하던 대로 앱을 먼저 띄워 공개 동선을 돌려보고(아래 "E2E 결과"), 그 결과를 근거로 코드를 봤습니다.

이번엔 좋은 소식이 큽니다. **9차에서 막아야 한다고 했던 두 [필수]가 모두 해결됐습니다.** 특히 6차부터 계속 이월되던 회원탈퇴가 드디어 닫혔고, Cloudinary 서명 건은 실제 업로드까지 돌려 확인했네요. 하나씩 짚어보겠습니다.

## 1. 지난(9차) 지적 반영 현황

| 9차 지적 | 상태 | 확인 |
| -------- | ---- | ---- |
| [필수] 회원탈퇴 실연결 (deleteUser + signOut) — 6차부터 이월 | **해결** | `withdraw/page.tsx`의 `handleDelete`(74행)가 이제 `await deleteUser(reasonText)`를 부르고(78행), 에러면 `setDeleteError`로 안내하고 멈춘 뒤, 성공하면 `clearUser()` → `await supabase.auth.signOut()`(89행)까지 갑니다. UI만 있던 게 실제 계정 삭제·로그아웃으로 이어졌습니다(gyuhwa). |

회원탈퇴는 가장 오래 끌던 항목이었는데, 이번에 에러 처리까지 갖춰서 깔끔하게 닫은 점이 좋습니다. "삭제 호출 한 줄" 붙이고 끝낸 게 아니라, 실패하면 모달을 닫고 사유를 보여주고 성공해야만 로컬 유저를 비우고 로그아웃하는 순서까지 정확히 짚어둔 게 보입니다.

## 2. Cloudinary 서명 — 실제 업로드로 확인했습니다

9차에서 "서명을 `crypto.createHash("sha256")`로 만드는데, Cloudinary 서명 업로드는 계정 설정을 바꾸지 않으면 SHA-1이 기본이라 `Invalid Signature`가 날 수 있다"고 [필수]로 짚었습니다. 이게 정말 문제가 되는지 확실히 해두려고, 이번엔 여러분 계정에 직접 업로드를 돌려봤습니다.

- 앱이 만드는 서명 문자열(`folder=...&timestamp=...` + secret)을 그대로 재현해서 **SHA-256으로 서명한 실제 업로드 → 성공**(asset_id 반환).
- 대조로 **일부러 틀린 서명을 보내니 `Invalid Signature`로 거절** — Cloudinary가 서명을 진짜로 검증하고 있고, 그 검증을 SHA-256 서명이 통과했다는 뜻이네요.
- (확인용으로 올린 테스트 이미지 2개는 곧바로 삭제해서 계정을 정리해뒀습니다.)

정리하면 **이 계정에서는 앱의 SHA-256 서명으로 업로드가 정상 동작**합니다. 9차의 [필수] 우려는 이 계정에 한해 해소된 셈이니, 시연에서 펫시터 등록 이미지 업로드는 자신 있게 보여주셔도 됩니다. 다만 한 가지만 팀 노트에 남겨두면 좋겠는데요, 지금 업로드가 되는 건 Cloudinary 계정 설정이 SHA-256을 받아주고 있기 때문입니다. 나중에 계정을 새로 파거나 환경이 바뀌면 똑같은 코드가 `Invalid Signature`로 막힐 수도 있으니, "우리는 SHA-256 서명을 쓴다"는 사실을 어딘가 적어두면 다음에 이 코드를 만지는 사람이 헤매지 않습니다.

> 참고: `upload.ts:12`의 `cloudName`은 `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME`을 읽는데, 환경파일에 이 변수(`dzocytofa`)가 잘 들어가 있어 문제 없었습니다.

## 3. 새로 들어온 것 — 실데이터 연동

9차 이후 흐름이 "더미 걷어내고 실데이터로 붙이기"에 집중돼 있네요. 시연에서 화면이 진짜 데이터로 도는 게 중요하니 방향이 좋습니다.

- **구인게시판 실데이터·조회수 (BestSeal/sealheal)** — 더미를 제거하고 `/api/requests`로 실제 글을 받아옵니다(E2E L10에서 실데이터 응답 확인). 조회수 연동에 작성/수정 확장까지 함께 들어왔습니다.
- **후기 관리 API 연동 (영은/0sliverchoi321z)** — 더미를 제거하고 받아온 후기를 API로 붙였는데, 페이지네이션·카운트 오류부터 탭 전환 시 중복 상태 초기화까지 잇따라 잡았습니다. 필터나 탭이 바뀔 때 상태가 어긋나는 류의 버그를 끝까지 따라가서 고친 흐름이 좋습니다.
- **펫 실데이터 (박규나/Gyu-me)** — 반려동물 더미를 걷어내면서, 로그인 사용자가 펫이 0마리일 때 더미가 잘못 뜨던 버그를 고쳤습니다. 데이터가 없을 때의 빈 상태까지 챙긴 수정이네요.

## 5. 시연까지 — 한 가지만

두 [필수]가 다 닫혀서, 시연 직전에 꼭 막아야 할 것은 남아 있지 않습니다. 다만 시연 운영 관점에서 한 가지만 미리 합의하고 들어가면 좋겠네요.

- **시연 범위를 팀이 명확히 정하기.** 관리자 기능이 아직 없으니 오늘은 자연스럽게 사용자 흐름 중심이 될 텐데, 어디까지 보여주고 미완성인 부분(가격/위치 입력, 관리자 등)은 어떻게 설명할지를 미리 정해두면 시연 중에 당황할 일이 줄어듭니다. 9차에 드린 이야기와 같은 결입니다.

이번 회차는 오래 끌던 회원탈퇴를 닫고, Cloudinary 업로드가 실제로 되는 것까지 확인했고, 화면이 더미가 아니라 진짜 데이터로 도는 단계로 올라왔습니다. 시연에서 사용자 흐름은 자신 있게 보여줄 수 있는 상태라 생각합니다. 화이팅입니다.

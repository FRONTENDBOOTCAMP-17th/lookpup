## 2. `[필수]` 빌드가 타입 체크에서 실패합니다 (실측)

`npm run build` — 컴파일은 되지만 타입 체크에서 멈춥니다.

```
✓ Compiled successfully
Failed to type check.
Type error: Property 'id' is missing in type '{ lat: number; lng: number; }'
but required in type 'MapMarker'.
  → src/app/petsitters/[id]/page.tsx:352
```

`KakaoMap`의 `MapMarker`는 `id: number`가 필수인데, 상세 페이지에서 `markers={[{ lat, lng }]}`로 id 없이 넘깁니다. `id`를 채우면 됩니다(예: `markers={[{ id: PETSITTER.id, lat: ..., lng: ... }]}`). 이게 지금 배포(production build)를 막습니다.

> 다른 타입 에러는 install 후 없었습니다. (참고: `@portone/browser-sdk/v2`가 한때 "모듈 없음"으로 보였는데, 제 로컬 node_modules가 오래된 탓이었고 `npm install` 후 사라졌습니다 — 학생 코드 문제 아님.)

## 3. `[필수]` 로그아웃이 세션을 끊지 않습니다 (1차 #4 미해결)

`signOut`이 프로젝트 어디에도 없습니다. 로그아웃 동작이 `router.push("/auth/login")`뿐이라, **화면만 로그인 페이지로 갈 뿐 Supabase 세션은 그대로 남습니다.** 주소창에 `/myprofile`을 다시 치면 여전히 로그인 상태로 들어가집니다.

```ts
const supabase = createClient();
await supabase.auth.signOut();   // ← 이게 빠져 있음
router.push("/auth/login");
```

---

## 4. `[필수]` 루트 `middleware.ts`가 없어 세션·보호 라우트가 안 돕니다 (1차 #2 미해결)

`utils/supabase/middleware.ts`(세션 갱신 헬퍼)는 잘 만들어져 있는데, 이를 호출하는 **프로젝트 루트의 `middleware.ts`(또는 `src/middleware.ts`)가 없어 한 번도 실행되지 않습니다.** 그래서 (a) 서버에서 세션 자동 갱신이 안 되고, (b) `/myprofile` 등 보호 라우트가 비로그인에게도 열립니다. 루트 middleware를 추가해 헬퍼를 연결하면 두 문제가 같이 풀립니다(가이드 참고).

## 5. 보안 — RLS (시도했으나 한계 있음)

anon 키로 직접 호출하니 `users`·`reviews`·`notifications`는 0행, `petsitters`·`bookings`·`boards`는 "테이블 없음"이 떴습니다. 빈 테이블인지 RLS 차단인지 구분하려 했으나 **제공된 service-role 키가 "Invalid API key"로 거부**되어 확정하지 못했습니다(아직 더미데이터 프론트 단계라 테이블이 비어 있을 가능성도 큼). → **실데이터를 붙이기 전에 모든 테이블 RLS를 켜고 정책을 정의**해 두세요. service-role 키도 최신인지 점검 부탁합니다.

## 6. 멤버별 리뷰

### 박규나 (Gyu-me) — `KakaoMap` / 펫시터 목록 / `bookingStore` / 메인·헤더

**잘한 점**
- `KakaoMap`: `onMarkerClickRef`로 최신 핸들러를 참조해 stale closure를 피하고, `autoload=false` + `kakao.maps.load(initMap)`로 SDK 비동기 로드를 정석대로 처리했습니다. 마커도 SVG data-URI로 인증 여부에 따라 색을 바꾸고요. 초보 단계에서 보기 드물게 꼼꼼합니다.
- 펫시터 목록 UI(E2E `images/2nd-02-petsitters-map.png`)는 검색·필터칩·인증뱃지·평점·가격까지 완성도가 높습니다.

**`[필수]`** 위 2번 — `petsitters/[id]`에서 마커에 `id` 누락(빌드 실패).

**`[제안]` 지도가 안 뜹니다 — 환경변수 이름 확인**
- 코드는 `process.env.NEXT_PUBLIC_KAKAO_MAP_KEY`를 읽는데, 전달받은 env엔 `KAKAO_MAP_KEY`(NEXT_PUBLIC_ 접두사 없음, `=` 앞뒤 공백)만 있습니다. 클라이언트에서 쓰려면 **반드시 `NEXT_PUBLIC_` 접두사**가 필요합니다. 제 리뷰 환경에서 임시로 `NEXT_PUBLIC_KAKAO_MAP_KEY`를 채웠는데도 지도 영역이 비어 나왔습니다(콘솔 에러는 없음). 카카오 JS 지도는 **개발자 콘솔에 도메인(localhost 포함)을 등록**해야 떠서, 그 설정도 함께 확인해 보세요. 두 가지(env 이름 + 도메인 등록)를 점검하면 해결될 가능성이 큽니다.

**`[제안]`** `KakaoMap`의 `useEffect` 의존성이 `[markers, center, level]`인데 `markers`/`center`는 매 렌더 새 참조라, 렌더마다 `initMap`이 다시 돌아 지도를 통째로 다시 만듭니다. 부모에서 `useMemo`로 안정화하거나, 마커만 갱신하는 식으로 바꾸면 깜빡임/누수를 줄일 수 있습니다.

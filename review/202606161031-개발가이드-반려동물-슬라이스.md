# 더미 화면을 서버 액션에 연결하기 — 반려동물(pets) 한 바퀴

이 문서는 lookpup에서 **하드코딩한 더미데이터 화면을 실제 Supabase 데이터로 연결하는 방법**을 처음부터 끝까지 따라갑니다. 예제로 반려동물(pets) 화면 하나를 골라 등록, 목록, 삭제까지 한 바퀴를 돌아봅니다. 이 한 바퀴를 손에 익히면 게시판이나 리뷰, 예약 내역 같은 다른 더미 화면도 **똑같은 순서로** 연결할 수 있습니다. 그게 이 문서의 진짜 목표라 생각합니다.

데이터를 다루는 코드(`src/app/actions/pets.ts`)는 이미 잘 만들어져 있습니다. 우리가 할 일은 그 코드를 **읽고, 화면에서 불러 쓰는 것**입니다. 새로 만드는 것보다 있는 걸 연결하는 게 먼저니, 부담 갖지 말고 천천히 따라와 주세요.

---

## 0. 큰 그림 — 지금 화면은 왜 "가짜"인가

`src/app/myprofile/mypets/page.tsx`를 열면 위쪽에 이런 코드가 있습니다.

```tsx
// 더미데이터
const INITIAL_PETS: Pet[] = [
  { id: "p1", name: "몽이", animal_type: "dog", breed: "골든 리트리버", ... },
  { id: "p2", name: "나비", animal_type: "cat", ... },
];
```

이건 **화면을 그려보려고 손으로 적어둔 가짜 데이터**입니다. 누가 로그인하든 항상 몽이, 나비, 코코만 보이죠. 실제로는 "지금 로그인한 사람이 등록한 반려동물"을 데이터베이스에서 가져와 보여줘야 합니다.

우리 프로젝트에서 데이터베이스(Supabase)와 이야기하는 통로가 **서버 액션(server action)** 입니다. `src/app/actions/` 폴더가 그 통로들이고, 반려동물은 `pets.ts`에 들어 있습니다. 흐름은 늘 이렇습니다.

```
화면(컴포넌트)  →  서버 액션(actions/*.ts)  →  Supabase(DB)
   불러서 쓴다        인증·검증·DB 작업          진짜 데이터
```

우리가 채울 빈칸은 가운데 화살표, **"화면이 서버 액션을 불러서 쓰는 부분"** 입니다.

---

## 1. 서버 액션 읽는 법 — `createPet` 해부

연결하기 전에 부를 대상을 먼저 읽을 줄 알아야 합니다. `src/app/actions/pets.ts`의 `createPet`을 한 줄씩 봅시다. 전체를 외울 필요는 없고, **무엇을 넣으면 무엇이 나오는지**만 보면 됩니다.

```ts
"use server"; // ← 이 파일의 함수들은 "서버에서 실행된다"는 표시. 맨 위에 한 번.

export async function createPet(input: PetInput) {
  const user = await getAuthUser();          // (1) 지금 로그인한 사람 확인
  if (!user) {
    return { error: { code: "UNAUTHORIZED", message: "로그인이 필요합니다." } };
  }

  if (!input.name || input.name.length > 20 || input.age < 0 /* ... */) {
    return { error: { code: "VALIDATION_ERROR", message: "입력값이 유효하지 않습니다." } }; // (2) 값 검증
  }

  const db = createServiceClient();
  // ... (3) 한 사람당 최대 10마리 같은 규칙 확인 ...

  const { data, error } = await db
    .from("pets")
    .insert({ ...input, owner_id: user.id })  // (4) DB에 한 줄 추가
    .select()
    .single();

  if (error) {
    return { error: { code: "INTERNAL_ERROR", message: error.message } };
  }
  return { data };                            // (5) 성공하면 만들어진 데이터를 돌려줌
}
```

여기서 **딱 두 가지만** 기억하면 됩니다.

1. **입력**: `createPet`은 `PetInput` 모양의 객체 하나를 받습니다. 그 모양은 파일 위쪽 `interface PetInput`에 적혀 있습니다.

   ```ts
   interface PetInput {
     name: string;
     animal_type: "dog" | "cat";
     breed?: string | null;
     age: number;          // 숫자입니다 (문자열 아님)
     gender: "MALE" | "FEMALE" | "MALE_NEUTERED" | "FEMALE_NEUTERED";
     weight: number;       // 숫자
     image_url?: string | null;
     caution?: string | null;
   }
   ```

2. **출력**: 우리 액션들은 항상 둘 중 하나를 돌려줍니다.
   - 성공: `{ data: ... }`
   - 실패: `{ error: { code: "...", message: "..." } }`

   그래서 화면에서는 늘 **`result.error`가 있는지 먼저 확인**하고, 없으면 `result.data`를 쓰면 됩니다. 이 약속이 모든 액션에서 똑같으니, 하나를 익히면 나머지도 똑같이 다룰 수 있습니다.

> 짚어둘 점이 있습니다. `gender`가 화면(`남아/여아` + `중성화` 체크)과 모양이 다릅니다. DB는 `MALE / FEMALE / MALE_NEUTERED / FEMALE_NEUTERED` 네 가지로 저장합니다. 이런 "화면 값 ↔ DB 값" 변환은 2단계에서 직접 맞춰줍니다. 이게 연결 작업의 핵심이라 생각합니다.

## 2. 등록 폼을 `createPet`에 연결하기

대상 파일: `src/app/pet-register/page.tsx`

지금 이 폼의 "등록하기" 버튼은 진짜 저장을 하지 않습니다. 아래처럼 알림창만 띄우고 끝나죠.

```tsx
const handleSubmit = () => {
  if (!petType) { alert("동물 종류를 선택해주세요."); return; }
  if (!name.trim()) { alert("이름을 입력해주세요."); return; }
  if (!gender) { alert("성별을 선택해주세요."); return; }
  alert("반려동물이 등록되었습니다!"); // ← 사실 아무것도 저장 안 함
};
```

이걸 **실제로 저장하도록** 바꿔보겠습니다.

### 2-1. 액션 가져오기 (import)

파일 맨 위 import들 아래에 한 줄 추가합니다.

```tsx
import { createPet } from "@/app/actions/pets";
```

서버 액션이지만 클라이언트 컴포넌트(`"use client"`)에서 이렇게 그냥 import해서 함수처럼 부르면 됩니다. 실제 실행은 서버에서 일어나고, 화면은 결과만 받습니다.

### 2-2. 제출 중 상태 만들기 (중복 클릭 방지)

버튼을 두 번 눌러 두 번 저장되는 사고를 막으려면 "지금 보내는 중" 상태를 하나 둡니다. 다른 `useState`들 근처에 추가하세요.

```tsx
const [submitting, setSubmitting] = useState(false);
```

### 2-3. 화면 값을 `PetInput` 모양으로 바꾸기

가장 중요한 부분입니다. 폼의 state를 액션이 원하는 모양으로 맞춰줍니다. 특히 **숫자 변환**과 **성별 합치기**를 조심하세요.

```tsx
// 남아/여아 + 중성화 여부 → DB가 쓰는 네 가지 값으로
function toGender(
  gender: "male" | "female",
  neutered: boolean
): "MALE" | "FEMALE" | "MALE_NEUTERED" | "FEMALE_NEUTERED" {
  if (gender === "male") return neutered ? "MALE_NEUTERED" : "MALE";
  return neutered ? "FEMALE_NEUTERED" : "FEMALE";
}
```

### 2-4. `handleSubmit`을 진짜로 바꾸기

```tsx
const handleSubmit = async () => {
  // (1) 화면 단 검증은 그대로 둡니다 — 빨리 사용자에게 알려주려고.
  if (!petType) { alert("동물 종류를 선택해주세요."); return; }
  if (!name.trim()) { alert("이름을 입력해주세요."); return; }
  if (!gender) { alert("성별을 선택해주세요."); return; }
  if (submitting) return; // 보내는 중이면 무시

  setSubmitting(true);
  try {
    // (2) 화면 값 → PetInput 모양
    const result = await createPet({
      name: name.trim(),
      animal_type: petType,                 // 이미 "dog" | "cat"
      breed: breed.trim() || null,
      age: Number(age),                     // 문자열 → 숫자
      weight: Number(weight),               // 문자열 → 숫자
      gender: toGender(gender, neutered),   // 위에서 만든 변환
      caution: notes.trim() || null,
      image_url: null,                      // 사진 업로드는 아래 "남은 것" 참고
    });

    // (3) 결과 처리 — error 먼저 확인하는 게 우리 약속
    if (result.error) {
      alert(result.error.message);          // 예: "로그인이 필요합니다."
      return;
    }

    // (4) 성공 → 목록 페이지로 이동
    alert("반려동물이 등록되었습니다!");
    router.push("/myprofile/mypets");
  } finally {
    setSubmitting(false);                   // 성공이든 실패든 잠금 해제
  }
};
```

마지막으로 버튼이 보내는 중에는 안 눌리도록 살짝 손봅니다.

```tsx
<button onClick={handleSubmit} disabled={submitting} /* ...기존 className... */>
  <span className="...">{submitting ? "등록 중..." : "등록하기"}</span>
</button>
```

여기까지 하면 등록이 **진짜로** 됩니다. 직접 확인해 보세요. 폼을 채우고 등록하면 mypets로 이동하고, 3단계까지 마치면 방금 등록한 아이가 목록에 보입니다. 지금은 목록이 아직 더미라 안 보일 텐데, 그건 다음 단계에서 고칩니다.

> 왜 화면 검증을 남겨두면서 액션도 검증할까요? 화면 검증은 **빠른 안내용**(사용자 편의)이고, 액션 검증은 **진짜 방어선**입니다. 화면 코드는 누구나 우회할 수 있어서, 서버 액션의 검증이 없으면 이상한 값이 DB에 들어갑니다. 그래서 둘 다 있는 게 정상입니다.

## 3. 목록을 가져올 액션 직접 만들기 — `getPets`

`pets.ts`에는 만들기(`createPet`), 수정(`updatePet`), 삭제(`deletePet`)는 있는데 **목록을 읽는 함수가 아직 없습니다.** 이번엔 그걸 추가합니다. 어렵지 않습니다. 기존 함수들의 모양을 그대로 따라 하면 됩니다. 옆에 있는 코드를 흉내 내면 컨벤션이 저절로 맞으니, 이건 좋은 습관이기도 합니다.

`src/app/actions/pets.ts` 맨 아래에 추가하세요.

```ts
export async function getPets() {
  const user = await getAuthUser();
  if (!user) {
    return { error: { code: "UNAUTHORIZED", message: "로그인이 필요합니다." } };
  }

  const db = createServiceClient();

  const { data, error } = await db
    .from("pets")
    .select("*")
    .eq("owner_id", user.id)        // 내 반려동물만
    .is("deleted_at", null)         // 삭제된 건 빼고
    .order("created_at", { ascending: false }); // 최근 등록 먼저

  if (error) {
    return { error: { code: "INTERNAL_ERROR", message: error.message } };
  }
  return { data };
}
```

`createPet`과 판박이죠. **로그인 확인, DB 작업, `{data}` 또는 `{error}` 반환.** 이 골격이 우리 액션의 표준입니다. `.eq("owner_id", user.id)`(내 것만)와 `.is("deleted_at", null)`(삭제된 것 제외)는 다른 목록에서도 자주 쓰니 눈에 익혀두면 좋습니다.

## 4. mypets 목록의 더미 걷어내기

대상 파일: `src/app/myprofile/mypets/page.tsx`

이제 가짜 `INITIAL_PETS` 대신 `getPets`로 진짜 목록을 가져옵니다.

### 4-1. 액션 가져오고, 상태로 관리하기

파일 위쪽에 import를 추가하고,

```tsx
import { useEffect, useState } from "react";
import { getPets } from "@/app/actions/pets";
```

컴포넌트 안에서 더미를 상태(state)로 바꿉니다. 지금은 아마 이렇게 더미를 바로 쓰고 있을 겁니다.

```tsx
// (전) 더미를 그대로 사용
const [pets, setPets] = useState<Pet[]>(INITIAL_PETS);
```

이걸 **빈 배열로 시작했다가 마운트될 때 불러오기**로 바꿉니다.

```tsx
// (후)
const [pets, setPets] = useState<Pet[]>([]);
const [loading, setLoading] = useState(true);

useEffect(() => {
  (async () => {
    const result = await getPets();
    if (result.data) {
      setPets(result.data.map(toView)); // toView는 아래 4-2 참고
    }
    setLoading(false);
  })();
}, []);
```

### 4-2. DB 데이터 ↔ 화면 데이터 맞추기

여기서 작은 문제가 하나 있습니다. 더미 `Pet`에는 `emoji`, `bgFrom`, `bgTo` 같은 **꾸밈용 필드**가 있는데 DB에는 없습니다(DB엔 `name/animal_type/breed/age/weight/gender/caution/image_url`만 있습니다). 그러니 DB 데이터를 화면이 기대하는 모양으로 살짝 바꿔주는 작은 함수를 둡니다.

```tsx
// DB 한 줄 → 화면이 쓰는 Pet 모양
function toView(row: any): Pet {
  const isDog = row.animal_type === "dog";
  return {
    id: row.id,
    name: row.name,
    animal_type: row.animal_type,
    breed: row.breed ?? "",
    age: row.age,
    weight: row.weight,
    gender: row.gender?.startsWith("MALE") ? "수컷" : "암컷", // DB값 → 화면 표기
    caution: row.caution ?? "",
    emoji: isDog ? "🐶" : "🐱",
    bgFrom: isDog ? "#FDE8C4" : "#D6EAF8",
    bgTo: isDog ? "#FAD7A0" : "#AED6F1",
  };
}
```

> 이렇게 "DB 모양"과 "화면 모양"이 다를 때 사이에서 변환해 주는 함수를 두는 건 흔한 패턴입니다. 나중에 여유가 되면 `emoji`와 색은 화면에서 계산하고 `Pet` 타입을 DB에 맞추는 쪽으로 정리해도 좋습니다. 지금은 화면을 안 망가뜨리는 게 우선이라 변환 함수로 다리를 놓습니다.

### 4-3. 비었을 때·불러오는 중 처리

마지막으로 목록을 그리는 부분 근처에서 두 경우를 챙겨줍니다.

```tsx
{loading ? (
  <p className="text-center text-[#6B7280] py-10">불러오는 중...</p>
) : pets.length === 0 ? (
  <p className="text-center text-[#6B7280] py-10">아직 등록한 반려동물이 없어요.</p>
) : (
  /* 기존 카드 목록 렌더 그대로 */
)}
```

이제 새로고침하면 **로그인한 내 계정의 진짜 반려동물**이 보입니다. 2단계에서 등록한 아이가 여기 나타나면 등록부터 목록까지 한 줄로 이어진 겁니다.

## 5. 삭제 연결하기 — `deletePet` + 확인 모달

mypets에는 이미 삭제 확인 모달(`DeleteModal`)이 있습니다. 지금은 모달의 "삭제하기"가 화면에서만 지우는 흉내일 가능성이 큽니다. 여기에 진짜 삭제를 붙입니다.

import에 `deletePet`을 더하고,

```tsx
import { getPets, deletePet } from "@/app/actions/pets";
```

삭제를 처리하는 함수를 만듭니다.

```tsx
const handleDelete = async (id: string) => {
  const result = await deletePet(id);
  if (result.error) {
    alert(result.error.message); // 예: "진행 중인 예약이 있어 삭제할 수 없습니다."
    return;
  }
  // 성공 → 화면 목록에서도 제거
  setPets((prev) => prev.filter((p) => p.id !== id));
};
```

그리고 모달의 확인 버튼이 이 함수를 부르도록 연결합니다.

```tsx
<DeleteModal
  pet={selectedPet}
  onClose={() => setSelectedPet(null)}
  onConfirm={async () => {
    await handleDelete(selectedPet.id);
    setSelectedPet(null); // 모달 닫기
  }}
/>
```

`deletePet`은 안에서 **소유권 확인**(남의 반려동물은 못 지움)과 **진행 중 예약 확인**까지 알아서 합니다. 그래서 화면에서는 결과의 `error`만 사용자에게 보여주면 됩니다. 액션이 방어를 맡고 화면은 결과만 전하는 것, 이 분담이 핵심입니다.

## 6. 같은 패턴으로 다른 화면도 — 이게 진짜 목표

방금 한 네 단계를 다시 보면, 화면이 무엇이든 순서가 똑같습니다.

1. **액션을 읽는다** — `src/app/actions/<도메인>.ts`에서 입력(`...Input`)과 출력(`{data}`/`{error}`)을 확인합니다.
2. **폼을 연결한다** — 화면 state를 액션 입력 모양으로 변환하고, `await 액션()`을 부른 뒤 `error`를 먼저 확인하고, 성공이면 이동하거나 갱신합니다.
3. **목록을 연결한다** — `useEffect`에서 목록 액션을 호출해 `setState`로 그리고, 비었을 때와 로딩을 처리합니다.
4. **삭제와 수정은** — 액션을 부르고 결과의 `error`만 처리한 뒤, 성공하면 화면 목록을 갱신합니다.

lookpup에는 이 순서를 그대로 적용할 더미 화면이 아직 많습니다.

- **리뷰**: `actions/reviews.ts` ↔ `myprofile/reviews/page.tsx`, `.../reviews/write/page.tsx`
- **예약 내역**: `actions/reservations.ts` ↔ `myprofile/booking-history/page.tsx`
- **게시판**: `actions/requests.ts` ↔ `board/page.tsx`, `board/write/page.tsx`

하나를 골라 위 4단계를 똑같이 밟아보세요. 막히더라도 "지금 어느 단계에서, 어떤 값이 안 맞는지"만 알면 거의 풀립니다. 대개 숫자 변환이나 화면값↔DB값 차이입니다. 한 바퀴를 직접 돌려본 것과 그렇지 않은 것의 차이는 이 다음부터 빠르게 벌어진다고 생각합니다. 천천히 그렇지만 끝까지 한 바퀴를 돌려봅시다.

## 남은 것 — 사진 업로드 (다음 단계)

위 2단계에서 `image_url: null`로 두고 넘어갔습니다. 사진은 파일을 그대로 DB에 넣는 게 아니라, **Supabase Storage에 업로드해서 받은 주소(URL)를 `image_url`에 저장**하는 별도 과정이 필요합니다. 한 바퀴(등록, 목록, 삭제)가 먼저 손에 익은 다음에 붙이길 권합니다. 그때 또 단계별로 정리해 드리겠습니다.

## 직접 확인하는 법 (E2E와 별개로 손으로)

1. `npm run dev`로 띄우고 로그인합니다.
2. `/pet-register`에서 반려동물을 등록하고, "등록되었습니다" 뒤에 `/myprofile/mypets`로 이동되는지 봅니다.
3. mypets에 방금 등록한 아이가 보이는지 확인합니다(보이면 목록 연결 성공).
4. 삭제하면 목록에서 사라지는지, 새로고침해도 그대로인지 봅니다. 그대로면 DB에서 진짜 지워진 것이니 성공입니다.

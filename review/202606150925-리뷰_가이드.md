# lookpup 5차 리뷰 해결 가이드 (2026-06-15)

리뷰에서 짚은 것들을 어떻게 고치는지 단계별로 적었습니다. 위에서부터 우선순위 순서입니다.

## 1. [필수] 빌드 복구 — myprofile의 죽은 `handleLogout` 제거

### 왜 중요한가
지금 `npx tsc --noEmit`과 `npm run build`가 이 한 줄 때문에 막혀 있습니다.

```
src/app/myprofile/page.tsx(342,11): error TS2304: Cannot find name 'createClient'.
```

빌드가 빨간불이면 배포도 막히고, 다른 조원이 자기 작업을 머지·확인할 때도 같은 에러에 부딪힙니다. 그래서 빌드 복구가 1순위입니다.

### 무엇이 문제인가
`myprofile/page.tsx`는 위에서 `signOut`만 import 합니다.

```ts
// src/app/myprofile/page.tsx:27
import { signOut } from "@/app/actions/auth";
```

그런데 341-342줄의 `handleLogout`은 import하지 않은 `createClient`를 부릅니다.

```ts
const handleLogout = async () => {
  await createClient().auth.signOut();   // createClient가 없음 → TS2304
  router.push("/");
};
```

핵심은, 이 `handleLogout`이 **어디에서도 호출되지 않는다**는 점입니다. 실제 로그아웃 버튼은 이미 `signOut`으로 잘 동작합니다.

```ts
// 490줄, 638줄
<button onClick={signOut}>로그아웃</button>
```

### 어떻게 고치나 (권장: 함수 통째로 삭제)
안 쓰는 함수가 빌드를 막는 상황이니, import를 추가하기보다 **함수를 지우는 게 깔끔합니다.**

```ts
// 이 블록(341-344줄 부근)을 통째로 삭제
const handleLogout = async () => {
  await createClient().auth.signOut();
  router.push("/");
};
```

지운 뒤 `router`를 더 쓰는 데가 없으면 `useRouter` import도 같이 정리하면 좋습니다(`npx tsc --noEmit`이 안 쓰는 변수까지 알려줍니다). 삭제 후 다시 `npx tsc --noEmit`을 돌려 0건이 나오는지 확인하세요.

> 만약 어떤 이유로 이 함수를 살려야 한다면, 위에 `import { createClient } from "@/utils/supabase/client";`를 추가하면 됩니다. 하지만 동작이 `signOut`과 겹치니 삭제를 권합니다.

## 2. [필수] 회원탈퇴 실연결 — 화면에 `deleteUser` + `signOut` 붙이기

### 왜 중요한가
지금은 버튼을 누르면 "탈퇴 완료" 화면만 뜨고 계정은 그대로 남습니다. 사용자는 탈퇴했다고 믿는데 데이터가 살아 있으면 개인정보·신뢰 문제가 됩니다. 액션(`deleteUser`)은 이미 잘 만들어져 있으니 화면 연결만 하면 됩니다.

### 지금 상태

```ts
// myprofile/settings/withdraw/page.tsx:66
const handleDelete = () => {
  setShowModal(false);
  setDone(true);          // 아무것도 안 지움
};
```

### 어떻게 고치나

```ts
import { deleteUser } from "@/app/actions/users";
import { signOut } from "@/app/actions/auth";

const [error, setError] = useState<string | null>(null);
const [loading, setLoading] = useState(false);

const handleDelete = async () => {
  setLoading(true);
  setError(null);
  try {
    await deleteUser();   // 진행 중 예약 차단 + deleted_at 소프트 삭제
    setShowModal(false);
    setDone(true);
    await signOut();      // 세션 종료 + redirect("/")
  } catch (e) {
    setError(e instanceof Error ? e.message : "탈퇴에 실패했습니다.");
    setShowModal(false);
  } finally {
    setLoading(false);
  }
};
```

포인트 셋입니다.

- `deleteUser()`가 진행 중 예약이 있으면 막도록 만들어져 있으니(`actions/users.ts:33-73`), 실패 시 `error` 메시지를 화면에 보여주세요. 무조건 "완료"로 넘어가면 안 됩니다.
- `signOut()`은 내부에서 `redirect("/")`까지 합니다. 그래서 따로 `router.push`가 필요 없습니다.
- `loading` 동안 버튼을 비활성화하면 중복 클릭을 막을 수 있습니다.

### 한 가지 정책 결정
`deleteUser`는 `deleted_at` 소프트 삭제만 합니다. 즉 Supabase 인증 계정(`auth.users`)은 그대로 남습니다. 같은 이메일로 재가입을 막을지, 일정 기간 후 완전 삭제할지는 팀이 정하면 됩니다. 완전 삭제가 필요하면 service-role 키로 Admin API 삭제까지 설계해야 하는데, 이건 6차에 같이 얘기해도 됩니다.

## 3. [제안] 조인 타입을 정석으로 — `as unknown as` 대신 generated types

### 왜 중요한가
이번에 TS2352를 `as unknown as`로 닫은 건 잘하셨습니다. 다만 이 방식은 "타입 검사를 한 번 끄고 다시 켜는" 우회라, 실제 데이터 모양이 바뀌어도 컴파일러가 못 잡아줍니다. 정석은 Supabase가 만들어주는 타입을 써서 컴파일러가 진짜 모양을 알게 하는 쪽입니다.

### 어떻게 하나
1. 스키마에서 타입을 생성합니다.

```bash
npx supabase gen types typescript --project-id <프로젝트ID> > src/types/database.types.ts
# 로컬이면: npx supabase gen types typescript --local > src/types/database.types.ts
```

2. 클라이언트에 타입을 붙입니다.

```ts
import { createClient } from "@supabase/supabase-js";
import type { Database } from "@/types/database.types";

const supabase = createClient<Database>(url, key);
```

이렇게 하면 조인 결과가 배열인지 객체인지를 컴파일러가 스키마(외래키 관계)에서 추론합니다. 그러면 `as` 단언 자체가 대부분 필요 없어집니다.

```ts
// 예: 1:N 관계는 배열, N:1 관계는 객체로 자동 추론
const { data } = await supabase
  .from("payments")
  .select("*, users(full_name, email)")
  .single();
// data.users 의 모양이 관계에 따라 타입으로 잡힘 → 단언 불필요
```

4곳(`payments.ts:89·120`, `applications.ts:125`, `api/sitters/[id]/route.ts:34`)을 한 번에 정리하면 좋습니다. Next 16 기준 자세한 패턴은 `node_modules/next/dist/docs/` 가이드도 한 번 보세요.

## 4. [제안] 헤더 초기 깜빡임 없애기

### 왜 생기나
`isLoggedIn` 초기값이 `false`라, 로그인한 사용자도 `getUser()` 응답이 오기 전 짧은 순간 비로그인 헤더를 봅니다.

### 어떻게 고치나
"아직 모름" 상태를 따로 둡니다.

```ts
const [authChecked, setAuthChecked] = useState(false);

supabase.auth.getUser().then(({ data: { user } }) => {
  if (user) { setIsLoggedIn(true); fetchUserProfile(user.id); }
  setAuthChecked(true);   // 판정 끝
});
```

렌더에서는 판정 전엔 로그인/비로그인 어느 쪽도 확정해 보여주지 않습니다.

```tsx
{!authChecked ? (
  <div className="w-20 h-8 rounded bg-gray-100 animate-pulse" />   // 스켈레톤
) : isLoggedIn ? (
  <UserMenu profile={userProfile} />
) : (
  <Link href="/auth/login">로그인</Link>
)}
```

이러면 "비로그인 → 로그인"으로 깜빡 바뀌는 게 사라집니다.

> 보너스: `myprofile`과 헤더가 둘 다 `users`를 조회하니, 나중에 `useUserProfile` 같은 공유 훅이나 zustand store로 한 번만 조회하게 묶으면 중복이 줄어듭니다. 지금 당장은 아니어도 됩니다.

## 5. [제안] 모바일 메뉴 자동 닫힘 되살리기 (effect 제거의 후속)

`useEffect`로 라우트 변화 시 메뉴를 닫던 코드를 지운 건 잘한 판단입니다. 다만 뒤로가기나 프로그램적 이동에선 메뉴가 안 닫힐 수 있어요. effect를 되살리지 않고 동작만 보존하려면, 메뉴 안의 모든 이동 트리거에서 닫아주면 됩니다.

```tsx
// Link뿐 아니라 메뉴 안에서 router로 이동하는 곳에도 closeMobileMenu 호출
const goAndClose = (href: string) => {
  setMobileMenuOpen(false);
  router.push(href);
};
```

뒤로가기까지 완벽히 잡으려면 결국 라우트 구독이 필요한데, 그건 무한 루프 위험이 없는 형태(예: `pathname` 변화 감지 + 이전 값 비교)라야 합니다. 지금 단계에선 "메뉴 안 이동 트리거에서 모두 닫기"로 충분하다고 봅니다.

## 6. [제안] 간단한 CI 빌드 게이트

### 왜 중요한가
빌드를 막는 에러가 회차마다 누군가의 층에서 나오고, 본인 아닌 사람은 손대기 어려워 오래 남습니다. PR을 머지하기 전에 자동으로 `tsc`와 `build`를 돌려 빨간불이면 머지를 막으면, "내 층은 빌드 통과로 머지"가 자연히 지켜집니다.

### 어떻게 하나
`.github/workflows/ci.yml`을 추가합니다.

```yaml
name: CI
on:
  pull_request:
    branches: [dev]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npx tsc --noEmit
      - run: npm run build
        env:
          NEXT_PUBLIC_SUPABASE_URL: ${{ secrets.NEXT_PUBLIC_SUPABASE_URL }}
          NEXT_PUBLIC_SUPABASE_ANON_KEY: ${{ secrets.NEXT_PUBLIC_SUPABASE_ANON_KEY }}
          NEXT_PUBLIC_KAKAO_MAP_KEY: ${{ secrets.NEXT_PUBLIC_KAKAO_MAP_KEY }}
```

GitHub repo Settings → Secrets에 환경변수를 넣고, `dev` 브랜치 보호 규칙에서 이 체크를 필수로 걸면 됩니다. 처음엔 `tsc --noEmit`만 걸어도 효과가 큽니다.

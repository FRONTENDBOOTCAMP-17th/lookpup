## 2. 현재 코드 기준 신규 문제

### 치명도 높음

- `src/hooks/queries/useEarnings.ts:4-8` — `fetchEarnings`가 `res.ok`를 확인하지 않음. 401/403/500 응답에도 `{ data: undefined }`를 그대로 반환해 TanStack Query가 "성공" 상태로 처리, 에러 UI 대신 깨진 정산 화면이 노출될 수 있음.

### 치명도 중간

- `src/components/chat/ChatClient.tsx` (2120줄, useState 35개+, useEffect 8개+) — 한 컴포넌트에 너무 많은 상태가 몰려 있어 한 기능 수정이 다른 상태에 의도치 않은 영향을 줄 위험. `:409` 자동 채팅방 선택 로직은 `refresh()` 1회 재시도 후 실패 시 사용자에게 아무 안내 없이 조용히 포기.
- `src/components/common/chat/chat_components.tsx` (2902줄) — 서로 무관한 모달/헬퍼가 한 파일에 뭉쳐 있어 리뷰·유지보수 난이도 높음.
- `src/app/actions/payments.ts:110,123,203,225` / `reservations.ts:661,845` — `as unknown as {...}` 캐스팅 반복. Supabase select 구조가 바뀌어도 컴파일 타임에 잡히지 않고 런타임에 `undefined` 접근으로 이어질 수 있음.
- `src/hooks/queries/useSitters.ts:30` — RPC 파라미터를 `as any`로 캐스팅해 `database.types.ts` 타입 체크를 우회. RPC 시그니처 변경 시 컴파일 에러 없이 런타임에서만 깨짐.
- `src/hooks/petsitters/usePetsitterLocation.ts:41` — `navigator.permissions.query` 실패(구형 브라우저 등)를 처리하지 않아 로딩/모달 상태가 멈출 수 있음.
- `src/store/userStore.ts:41` — `clearUser`/`setDeletedAccount`에서 `unreadCount`를 리셋하지 않아, 공유 브라우저에서 새 세션 로그인 시 이전 사용자의 안읽음 배지 수가 남아있을 수 있음.

### 치명도 낮음

- `src/components/chat/ChatClient.tsx` 20곳 이상의 catch 블록이 에러를 로깅 없이 일반 메시지로 삼켜, 운영 중 전송/수락/거절/결제 실패 원인 추적이 어려움.
- `src/app/actions/reservations.ts` (1632줄 단일 파일) — 예약 생성/상태변경/완료확인 등 성격이 다른 로직이 한 파일에 혼재.
- `src/hooks/petsitters/usePetsitterLocation.ts:84` — 카카오맵 SDK 로드 대기용 100ms `setInterval` 폴링에 최대 재시도 제한이 없어, SDK 로드 실패 시 무한 폴링.
- `src/hooks/useImageUpload.ts:18` — `useSingleImageUpload`/`useMultiFileUpload` 간 파일/미리보기 상태 로직 중복, `URL.revokeObjectURL` 미호출로 블롭 URL 누수 가능.

## 3. 우선순위별 수정 제안

### 1순위

- `useEarnings.ts`의 `fetchEarnings`에 `res.ok` 체크 추가 후 실패 시 throw — 정산 화면이 조용히 깨지는 걸 막는 가장 저비용 수정.

### 2순위

- `userStore.ts`의 `clearUser`/`setDeletedAccount`에 `unreadCount` 리셋 추가 (공유 기기 세션 오염 방지).
- `usePetsitterLocation.ts`의 permissions 쿼리 실패 처리 및 카카오맵 폴링에 최대 시도 횟수 추가.

### 3순위 (여유 있을 때)

- `ChatClient.tsx`/`chat_components.tsx` 분리(기능별 하위 컴포넌트로), 에러 로깅 보강.
- `payments.ts`/`reservations.ts`의 반복되는 `as unknown as` 캐스팅을 공용 타입 헬퍼로 정리.
- `useSitters.ts`의 `as any` RPC 파라미터를 `database.types.ts` 기반 타입으로 교체.
- `useImageUpload.ts`의 두 훅 로직 통합 및 `revokeObjectURL` 정리.

## 4. 수정 전 확인이 필요한 사항

- `useEarnings.ts` 수정 시 `/api/earnings` 라우트가 실제로 401/403 등 비-200 상태를 반환하는지 먼저 확인 필요.
- `ChatClient.tsx`/`chat_components.tsx` 분리는 UI/기능 변경 없이 순수 구조 리팩토링이 가능한지 범위를 먼저 정해야 함 — 마감 전이라면 3순위에 두고 발표 이후로 미루는 것을 권장.
- `userStore.ts`의 `unreadCount` 리셋이 다른 실시간 구독 로직과 타이밍이 얽혀 있는지 확인 필요.

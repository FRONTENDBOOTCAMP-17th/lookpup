# lookpup 6차 리뷰 해결 가이드 (2026-06-16)

리뷰에서 짚은 것들을 어떻게 고치면 되는지 단계별로 적었습니다. 우선순위는 리뷰 7장 순서와 같습니다.

---

## 1. 빌드 복구 — myprofile 죽은 `handleLogout` 제거

`npx tsc --noEmit`에서 단 한 줄이 빌드를 막고 있습니다.

```
src/app/myprofile/page.tsx(272,11): error TS2304: Cannot find name 'createClient'.
```

이 함수는 어디에서도 호출되지 않습니다. 실제 로그아웃은 `signOut` server action으로 이미 동작하고 있으니, **함수를 통째로 지우면** 됩니다.

```ts
// src/app/myprofile/page.tsx:271-274  ← 이 블록을 삭제
const handleLogout = async () => {
  await createClient().auth.signOut();
  router.push("/");
};
```

지운 뒤 `router`가 다른 곳에서도 안 쓰이면 같이 정리하고, `npx tsc --noEmit`을 다시 돌려 0 에러를 확인합니다. import에 `createClient`를 추가하는 방향은 권하지 않습니다 — 안 쓰는 코드를 살리려고 의존성을 더하는 셈이라, 죽은 함수는 없애는 게 맞습니다.

## 2. 회원탈퇴 실연결 — `deleteUser` + `signOut` + 서버 가드

지금 `handleDelete`는 화면만 "완료"로 바꿉니다.

```ts
// settings/withdraw/page.tsx:64-67
const handleDelete = () => {
  setShowModal(false);
  setDone(true);   // 실제로는 아무것도 지우지 않음
};
```

`deleteUser()`(`actions/users.ts`)는 이미 잘 만들어져 있으니, 화면에서 호출만 붙이면 됩니다.

```ts
const [submitting, setSubmitting] = useState(false);
const [errorMsg, setErrorMsg] = useState("");

const handleDelete = async () => {
  setSubmitting(true);
  setErrorMsg("");
  try {
    await deleteUser(/* 필요하면 사유 selectedReason / otherText 전달 */);
    await signOut();        // actions/auth.ts — 세션 정리
    setShowModal(false);
    setDone(true);          // 진짜로 지워진 뒤에만 완료 화면
  } catch (e) {
    setShowModal(false);
    setErrorMsg(e instanceof Error ? e.message : "탈퇴 처리에 실패했습니다.");
  } finally {
    setSubmitting(false);
  }
};
```

포인트:
- **성공한 뒤에만 `setDone(true)`** 합니다. 실패하면 에러를 보여주고 계정은 그대로 둡니다. 지금처럼 무조건 완료 화면을 띄우면 사용자는 탈퇴됐다고 믿는데 데이터가 남습니다.
- `deleteUser`가 진행 중 예약을 막는다면, 그 에러 메시지를 `errorMsg`로 그대로 노출하면 됩니다. 지금 `hasActiveBookings = false` 하드코딩(53-54줄)도 실제 조회로 바꿔야 "예약 내역 보기" 분기가 의미를 가집니다.

**서버 가드.** 이 페이지는 비로그인에서도 폼이 풀로 렌더됩니다(E2E L7). 미로그인 사용자가 들어오면 로그인으로 보내는 게 맞습니다. server component 가드를 두거나, 클라 페이지라면 마운트 시 세션을 확인해 없으면 `router.replace("/auth/login")` 하세요.

```ts
// 예: 클라에서 가드
useEffect(() => {
  createClient().auth.getUser().then(({ data: { user } }) => {
    if (!user) router.replace("/auth/login");
  });
}, [router]);
```

(소프트 삭제만이면 `auth.users` 인증 계정은 남는다는 점도 정책으로 정해두면 좋습니다.)

## 3. CI 빌드 게이트 — 빨간 빌드는 머지 안 되게

같은 빌드 에러가 5차·6차 연속 남았습니다. 사람의 주의력에 맡기지 말고 자동으로 막읍시다. GitHub Actions에 워크플로 하나만 추가하면 됩니다.

```yaml
# .github/workflows/ci.yml
name: CI
on:
  pull_request:
    branches: [dev, main]
jobs:
  typecheck-build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx tsc --noEmit
      - run: npm run build
```

그다음 GitHub 저장소 Settings → Branches에서 `dev`를 보호 브랜치로 두고, 위 체크를 "required status check"로 지정하면, **빌드가 빨간 PR은 머지 버튼 자체가 막힙니다.** 그러면 "내 층은 빌드 통과로 머지"가 규칙이 아니라 시스템으로 강제됩니다.

## 4. 펫 다중 선택 — 두 배열을 하나로 묶기

지금은 `petIds`와 `petNames`를 따로 들고, 해제할 때 `petNames`를 이름으로 거릅니다. 동명 펫이 둘이면 한 마리만 해제해도 둘 다 빠져서 두 배열의 순서가 어긋납니다.

```ts
// store/bookingStore.ts — 한 배열로
type SelectedPet = { id: number; name: string };

interface BookingState {
  // petIds / petNames 대신
  pets: SelectedPet[];
  togglePet: (id: number, name: string) => void;
  // ...
}

togglePet: (id, name) => {
  const { pets } = get();
  set({
    pets: pets.some((p) => p.id === id)
      ? pets.filter((p) => p.id !== id)   // id 하나로만 토글
      : [...pets, { id, name }],
  });
},
```

이러면 이름이 같아도 `id`로만 더하고 빼니 어긋날 일이 없습니다. 화면에서는 `pets.map((p) => p.name)`로 이름 목록을, `pets.map((p) => p.id)`로 id 목록을 그때그때 뽑아 쓰면 됩니다. "한 데이터는 한 곳에"가 이런 어긋남을 막는 원리입니다.

## 5. 결제 서버 확정 + 웹훅

`usePortOne` 훅 자체는 잘 만들었습니다. 빠진 건 **결제를 서버가 다시 확인하는 단계**입니다. 지금은 브라우저가 "성공"이라고 하면 그대로 믿습니다. 두 가지를 더하면 됩니다.

### (1) 결제 단건 확정 라우트

`onSuccess`에서 곧장 완료 모달을 띄우지 말고, 서버에 paymentId를 보내 PortOne API로 실제 결제·금액을 대조한 뒤 완료를 확정합니다.

```ts
// app/api/payments/complete/route.ts (개념)
export async function POST(req: Request) {
  const { paymentId, expectedAmount } = await req.json();
  // PortOne 단건 조회 (서버에서, 시크릿 키로)
  const res = await fetch(`https://api.portone.io/payments/${paymentId}`, {
    headers: { Authorization: `PortOne ${process.env.PORTONE_API_SECRET}` },
  });
  const payment = await res.json();
  // 금액 대조 — 위변조 차단
  if (payment.amount.total !== expectedAmount) {
    return Response.json({ ok: false, reason: "amount_mismatch" }, { status: 400 });
  }
  if (payment.status !== "PAID") {
    return Response.json({ ok: false, reason: "not_paid" }, { status: 400 });
  }
  // 여기서 DB에 예약/결제 확정 저장
  return Response.json({ ok: true });
}
```

```ts
// payment/page.tsx onSuccess
onSuccess: async () => {
  const res = await fetch("/api/payments/complete", {
    method: "POST",
    body: JSON.stringify({ paymentId, expectedAmount: total }),
  });
  const data = await res.json();
  setShowPayModal(false);
  if (data.ok) setShowSuccessModal(true);
  else /* 실패 처리 */;
},
```

`expectedAmount`도 결국 클라가 보내지만, **서버는 PortOne이 알려준 실제 결제 금액과 대조**하므로 URL의 `?amount=100` 같은 위변조가 통하지 않습니다. 핵심은 "프런트가 보고한 성공"이 아니라 "서버가 PortOne에 직접 물어 확인한 성공"을 정본으로 삼는 것입니다.

### (2) 웹훅

브라우저가 죽어서 `onSuccess`가 안 와도 결제는 됐을 수 있습니다. PortOne 콘솔에 웹훅 URL(`/api/payments/webhook`)을 등록하고, 거기서 결제 상태를 받아 DB를 확정하세요. 그러면 프런트 모달은 보조 표시, 웹훅이 진짜 정본이 됩니다.

추가로, 결제 `customer`의 `"테스트"`/`"010-0000-0000"` 하드코딩(`payment/page.tsx:90-92`)은 로그인 사용자 정보로 채우는 자리로 표시해두면 좋습니다.

## 6. 카카오 지도 빈 화면 — 콘솔 도메인 등록

펫시터 목록 좌측 지도가 흰 화면입니다(E2E L2). 카카오 지도 JS SDK는 허용된 도메인에서만 뜹니다. 카카오 개발자 콘솔 → 내 애플리케이션 → 플랫폼 → Web에 **사이트 도메인**으로 `http://localhost:3000`(과 배포 도메인)을 등록하면 로컬에서도 지도가 보입니다. 코드 문제가 아니라 콘솔 설정이라, 등록 후 새로고침으로 확인하면 됩니다.

## 7. 게시판 정렬 드롭다운 — 연결하거나 정리하거나

지금은 `SORT_OPTIONS = ["최신순"]` 하나뿐이고 `onSortChange`가 연결돼 있지 않아, 드롭다운을 열어도 정렬이 안 바뀝니다. 둘 중 하나로 정리하세요.

- **연결**: `"조회순"`을 다시 넣고, `board/page.tsx`에서 `sortBy` state + `onSortChange`를 `SearchFilterBar`에 넘긴 뒤, `filtered.sort(...)`를 `sortBy`에 따라 분기.
- **정리**: 옵션이 하나뿐이면 필터 버튼을 잠시 숨겨 사용자가 "눌러도 안 바뀐다"고 느끼지 않게.

어느 쪽이든 "열리는데 동작은 안 함" 상태만 피하면 됩니다.

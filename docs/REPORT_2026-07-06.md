## 진행 상황 요약

19차 코드 리뷰(발표 D-2)와 마감 전 최종 점검 권고에 따라 움직인 하루로, 미승인 펫시터의 구인글 지원·재등록·자기 자신에 대한 예약을 차단하는 관리자 승인 체계가 새로 도입되고, 결제 로직(1원 결제 차단, 추가금 결제 실패·취소 시 상태 복구, 중복 결제 카드 문제)이 여러 차례에 걸쳐 다듬어짐. 18차 코드 리뷰에서 지적된 lint 경고들(렌더링 중 상태·ref 직접 갱신, useMounted 공용 훅 추출 등)을 렌더링 중 처리 패턴으로 정리하는 리팩토링이 지속되었고, 채팅 사이드바·카카오맵·GoTrueClient 중복 생성 등 다수의 버그가 함께 수정됨.

---

## 주요 성과

- 미승인 펫시터의 구인글 지원, `/sitter-register` 재접근, 자기 자신에게 예약하는 것을 차단하는 관리자 승인 체계 도입
- 결제 로직 반복 개선 — 1원 결제 차단, 추가금 결제 실패·취소 시 상태 복구, 다중 결제 요청 카드 잔존 문제 수정
- 18차 코드 리뷰 lint 경고 정리 — 렌더링 중 상태·ref 직접 갱신을 이펙트 밖 처리로 전환, useMounted 공용 훅 추출
- 채팅 메시지 중복 수신 시 key 충돌 방지, 채팅 사이드바 메시지 길이 제한 추가, 중복 생성되던 GoTrueClient 인스턴스 통합
- LocationPickerWithMap 지도 사라짐 버그 수정, 메인화면 펫호텔 아이콘 삭제

## 이슈 및 리스크

### 추가금 결제 실패·취소 시 상태 미복구

- **증상:** 추가금 결제가 실패하거나 취소되어도 요청 상태가 pending으로 복구되지 않아 재결제가 불가능해지던 문제
- **해결:** 결제 실패·취소 시 상태를 pending으로 되돌리도록 수정

### 다중 결제 요청 카드 잔존

- **증상:** 한 채팅방에 결제 요청이 여러 개 있을 때, 하나를 결제 완료해도 다른 카드가 계속 "결제하기" 상태로 남아있던 문제
- **해결:** 결제 완료 시 관련 카드 상태를 함께 동기화하도록 수정

### 채팅방 재사용 시 결제 요청 차단

- **증상:** 채팅방을 재사용할 경우 과거 결제 이력이 남아있어 새 결제 요청이 막히던 문제
- **해결:** 예약 단위로 결제 이력을 구분하도록 수정
